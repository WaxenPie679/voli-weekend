# Motore 400 € / 12 mesi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ricerca ogni 15 minuti fino a 400 € e 13 weekend; file Premium notturno (Weekend mesi 4–12, Weekend lunghi mesi 1–12) dallo storico; via Google; Telegram solo per il check-up.

**Architecture:** Le regole Weekend / Weekend lungo escono da `web/storico-view.js` in un modulo puro condiviso `web/weekend-trips.js`, usato dalla pagina dello storico e da `src/history/premium.js`. `runHistory` alla fine del giro calcola il file Premium dallo stato in memoria (sa cosa è stato riletto stanotte) e lo scrive accanto ai dati; il workflow lo pubblica sul branch `data`. La webapp converte le voci Premium in itinerari e le mostra con un interruttore Weekend / Weekend lungo.

**Tech Stack:** Node 24 ESM, luxon, `node --test`, GitHub Actions, webapp vanilla JS.

**Spec:** `docs/superpowers/specs/2026-11-24-motore-400-12-mesi-design.md`

## Global Constraints

- Prezzo massimo 400 € andata e ritorno; cursore della webapp da 20 a 400, passo 10, valore iniziale 100.
- Ricerca diretta: 13 weekend (`upcomingWeekends(now, 13)`).
- Premium: Weekend con venerdì successivo all'ultimo venerdì dei 13 della ricerca, fino a 53 sabati (`weekendSaturdays`); Weekend lunghi su tutti i 53 sabati; totale ≤ 400 €.
- Weekend: andata ven (sera) o sab, ritorno dom. Weekend lungo: andata gio/ven/sab, ritorno dom/lun.
- Venerdì sera: Ryanair se la partenza è ≥ 18:00; Wizz solo se **tutte** le partenze del giorno sono ≥ 18:00.
- Gamba non riletta stanotte: data dell'ultimo prezzo visto; più vecchia di 7 giorni → non si usa.
- Weekend lunghi mai in `direct*.json`.
- Nessun messaggio Telegram per voli o tratte seguite; il check-up (`health`) continua a scrivere su Telegram.
- Nessun riferimento a Google / `connections` resta in `src/`, `web/`, `test/`, `.github/`.
- Un errore nel calcolo Premium non cambia l'esito né i file dello storico.

## Review Focus

- Storico vuoto o gruppo nuovo con pochi giorni → file Premium valido con elenco vuoto, nessun crash (test in Task 5).
- Tratta con andata ma senza ritorno con prezzo → nessuna voce (Task 5).
- Gamba con prezzo `esaurito` / `nessun_volo` come ultimo stato → ignorata (Task 5).
- `premium.json` assente (404, prima notte) → la webapp funziona con i soli voli diretti (Task 7).
- Filtro «Sul posto» attivo con voci Premium senza orario di arrivo → escluse, non con ore sbagliate (Task 7).
